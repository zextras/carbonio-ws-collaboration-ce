# Backend XMPP messages

Chats communicates with the messaging server to describe changes that occur in the room.
These messages have to be considered useful only for maintaining the chat history of the room.

## Messages list

### New member added

This message is generated by MongooseIM, it is not editable by Chats.

```xml
<message from='[1]' to='[2]' id='*' type='groupchat' xmlns='jabber:client'>
  <x xmlns='urn:xmpp:muclight:0#affiliations'>
    <prev-version>*</prev-version>
    <version>*</version>
    <user affiliation='member'>[3]</user>
  </x>
  <body/>
  <stanza-id by='[1]' id='*' xmlns='urn:xmpp:sid:0'/>
</message>
```

Where:

1. identifier with domain of the owner who added the member
2. room identifier with domain
3. identifier with domain of the new member

### Room name changed

This message is generated by Chats, it can be changed if necessary.

```xml
<message from='[1]/[2]' to='[2]' id='*' type='groupchat' xmlns='jabber:client'>
  <x xmlns='urn:xmpp:muclight:0#configuration'>
    <operation>roomNameChanged</operation>
    <value>[3]</value>
  </x>
  <body/>
  <stanza-id xmlns="urn:xmpp:sid:0" by="[1]" id="*" />
</message>
```

Where:

1. identifier with domain of the owner who changed the name
2. room identifier with domain
3. the new room name

### Attachment added

This message will be generated by Chats, it can be changed if necessary.

```xml
<message from='[1]/[2]' to='[2]' id='*' type='groupchat' xmlns='jabber:client'>
  <x xmlns='urn:xmpp:muclight:0#configuration'>
    <operation>attachmentAdded</operation>
    <attachment-id>[3]</attachment-id>
    <filename>[4]</filename>
    <mime-type>[5]</mime-type>
    <size>[6]</size>
  </x>
  <body>[7]</body>
  <reply to='[2]' id='[8]' xmlns='urn:xmpp:reply:0' />
  <stanza-id by='[1]' id='*' xmlns='urn:xmpp:sid:0'/>
</message>
```

Where:

1. identifier with domain of the sender
2. room identifier with domain
3. attachment identifier useful for requiring the file or the preview
4. original file name of the attachment
5. file mime type
6. file size in bytes
7. message accompanying the attachment
8. identifier of the message to which you are replying

### Meeting started

This message is generated by Chats when a one-to-one meeting is started.

```xml
<message xmlns='jabber:client'
         to='[1]'
         from='[2]'
         type='groupchat'>
  <x xmlns='urn:xmpp:muclight:0#configuration'>
    <operation>meetingStarted</operation>
    <timestamp>[3]</timestamp>
  </x>
  <body/>
</message>
```

Where:

1. `to`: room identifier with MUC domain
2. `from`: identifier with domain of the user who started the meeting
3. `timestamp`: epoch milliseconds when the meeting was started

### Meeting ended

This message is generated by Chats when a one-to-one meeting is ended.

```xml
<message xmlns='jabber:client'
         to='[1]'
         from='[2]'
         type='groupchat'>
  <x xmlns='urn:xmpp:muclight:0#configuration'>
    <operation>meetingEnded</operation>
    <timestamp>[3]</timestamp>
    <startedAt>[4]</startedAt>
    <duration>[5]</duration>
  </x>
  <body/>
</message>
```

Where:

1. `to`: room identifier with MUC domain
2. `from`: identifier with domain of the user who ended the meeting
3. `timestamp`: epoch milliseconds when the meeting was ended
4. `startedAt`: epoch milliseconds when the meeting was started
5. `duration`: duration in seconds
